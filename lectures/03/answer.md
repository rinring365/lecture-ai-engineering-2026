## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 素のLLM（app.ask）は、モデル自身の知識だけで長く一般的な解説をした（出力587〜864トークン）。画像生成AIでの使われ方や「付箋」のたとえなど、講座と関係の薄い内容が多く、実行するたびに構成が変わった。出典もない。gemini-3.5-flashでは通信規格の「LoRa」まで説明する回があり、講座の文脈がわからないことによるずれが見られた。
  - エージェント（app.agent）は、用語集の定義に沿って短く答えた（出力約200トークン）。「（第2回）」と出典を示し、複数回実行しても内容はほぼ同じだった。
  - 一方で入力トークンは、素のLLMの7に対し、エージェントは約1,300に増えた。システムプロンプト、ツール定義、ツールの返り値が入力に含まれるためである。

- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 「LoRAとQLoRAの違いは？」→ `search_glossary({'query': 'LoRA'})`、`search_glossary({'query': 'QLoRA'})`（並列に2回）
  - 「ファインチューニングとは？」→ `search_glossary({'query': 'ファインチューニング'})`
  - 「RAGとファインチューニングはどう使い分ける？」→ `search_glossary({'query': 'RAG'})`、`search_glossary({'query': 'ファインチューニング'})`。RAGの検索結果が無関係な「一致率」だったため、`search_glossary({'query': 'RAG'})` をもう一度呼んだ。

- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 通常は2回。1回目でツール呼び出しを決め、2回目でツールの結果をもとに回答を生成する。
  - RAGの質問では、検索をやり直したため3回に増えた（入力トークンも約2,400に増加）。

- 追加したツールと、docstring に書いた説明：
def make_quiz(lecture: int) -> str:
    """指定した回の用語から1つを選び、確認問題と答えを返す。

    「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。
    """
    terms = [term for term in load_glossary() if term["lecture"] == lecture]
    if not terms:
        return f"第{lecture}回の用語が用語集に見つかりませんでした。"

    term = random.choice(terms)
    return json.dumps(
        {
            "question": f"「{term['term']}」の意味は？",
            "answer": term["definition"],
        },
        ensure_ascii=False,
    )

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - `agent.py` のシステムプロンプトから「用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。」の一文を消し、一文がある場合とない場合で同じ質問の結果を比べた。
  - 質問は「LoRAとQLoRAの違いは？」「ファインチューニングとは？」「RAGとファインチューニングはどう使い分ける？」の3つで、各条件1回ずつ実行した。
- 結果：
  - 3つの質問すべてで、一文の有無にかかわらず `search_glossary` が同じように呼ばれた。RAGの検索をやり直す動きも、両方の条件で起きた。
  - 用語を直接含む質問（LoRA/QLoRA、ファインチューニング）では、回答内容に実質的な差はなかった。
  - RAGの質問では、回答の書き方に差が出た。一文ありでは、用語集に根拠のある項目にだけ出典を付け、RAGについては「※用語集より」と根拠の範囲を示した。一文なしでは、モデル自身の知識による例（社内マニュアルなど）を加えたうえで、全体に「第2回」と出典を付けていた。
  - 入力トークンは一文なしのほうが1リクエストあたり約24少なかった（2リクエストで−48、3リクエストで−72）。
- 気づき・疑問：
  - ツールを呼ぶかどうかは、システムプロンプトの指示がなくても、ツールの説明（docstring）だけで決まっていた。docstringの書き方が、ツールが使われるかどうかに大きく効いていると考えられる。
  - この一文は、ツールを呼ぶきっかけよりも、用語集を根拠として重視し、根拠のない内容と区別する姿勢に効いている可能性がある。ただし各条件1回ずつなので、生成のばらつきと区別するには複数回の試行が必要である。
  - `search_glossary('RAG')` で無関係な「一致率」が返った。用語集にRAGの項目がないのか、検索方法に問題があるのかを確かめたい。また、見つからなかったときに「該当なし」と返すようにすれば、同じ検索の無駄なやり直しを防げるのではないか。
